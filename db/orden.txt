# Orden de aplicación del esquema sobre una base VACÍA.
#
# Los archivos de db/ son incrementales y en su mayoría idempotentes, pero NO son
# independientes. Dependencias reales que fijan este orden:
#   · modalidad-comercial-b1.sql crea reserva_hhmm_a_minutos y necesita `mensualidades`,
#     así que va DESPUÉS de mensualidades-m2.
#   · empresas-b7-*.sql usan reserva_hhmm_a_minutos → después de modalidad-comercial-b1.
#   · gift-cards-alta-administrativa.sql y facturacion-eventos-canonica.sql leen
#     mensualidad_compras → después de mensualidades-m3.
#   · ia-sim-bloque4c.sql inserta en storage.buckets → el stack local necesita Storage.
#
# NO se aplican (son diagnósticos, no migraciones): los *.previo.sql, los
# *.verificacion.sql, modalidad-comercial-b1.matriz-legacy.sql y b2-motor-vs-trigger.sql
# (una matriz de 577 casos que termina SIEMPRE con RAISE EXCEPTION para revertirse).
#
# Una línea por archivo, en orden. Las líneas que empiezan con # se ignoran.
# Lo usa scripts/pruebas/aplicar-esquema.mjs.
